## 0. 本次结构修正：资金表禁止软删除（双库落地）

按 `DB_CONVENTIONS.md` §4 方案 A，以下 **6 张资金/账务表**已从 MySQL 与 PG 基线移除 `deleted_at` 列及其索引：

| 表 | 表语义 |
| --- | --- |
| tx_payments | 支付单 |
| tx_refunds | 退款单 |
| mch_merchant_balances | 商家资金余额 |
| mch_merchant_withdrawals | 商家提现 |
| mch_merchant_settlement_logs | 商家结算流水 |
| mch_settlement_details | 结算明细 |

要点：
- 资金表**只可追加/状态流转**，异常冲正禁止删行 —— 用状态（如 `failed`/`rejected`）与冲正流水表达；
- `tx_order_items`/`tx_sub_orders`/`tx_orders` **保留软删除**（非资金表：订单可作废/隐藏，不影响资金审计）；
- 复核脚本：`sql/audit/p1_funds_append_only_audit.sql`（MySQL）/ `pgsql/audit/p1_funds_append_only_audit.sql`（PG）。

> **存量库迁移**：`ALTER TABLE <t> DROP COLUMN deleted_at;` + 删除 `idx_deleted_at`（MySQL）/ 部分索引（PG，建库脚本已同步，已有库需手动执行一次；P2 migration 体系落地前以本说明为准）。

## 1. 资金核对链（Money Chain）

```text
订单 tx_orders / tx_sub_orders
  → 支付 tx_payments（paid）           —— 资金流入
  → 退款 tx_refunds（success）         —— 资金流出（可部分）
  → 商家应收 mch_settlement_details    —— 按订单明细计应收
  → 平台佣金 commission_amount 扣减
  → 结算 mch_merchant_settlement_logs  —— 生成结算单
  → 提现 mch_merchant_withdrawals      —— 余额 → 银行
  → 余额 mch_merchant_balances         —— 可提现/冻结变动
```

### 1.1 各环节记账口径

| 环节 | 触发 | 记账 |
| --- | --- | --- |
| 订单实付 | 下单 | `tx_orders.pay_amount`、`tx_sub_orders.pay_amount`、`tx_order_items.price×qty` |
| 支付成功 | 回调 success | `tx_payments.amount` 增加（`status=paid`） |
| 退款成功 | 渠道 success | `tx_refunds.amount`；冲减 `tx_order_items.refund_amount`、订单可退余额 |
| 应收入账 | 支付成功（订单完成可结算时） | `mch_settlement_details(order_amount=pay_amount, commission_amount=pay_amount×commission_rate‰, settlement_amount=order_amount−commission_amount−refund_amount)` |
| 结算单 | 结算周期到 | `mch_merchant_settlement_logs`（Σ 明细） |
| 提现 | 商家申请 → 打款 | `mch_merchant_withdrawals.amount` 冻结→扣除 `mch_merchant_balances` |

### 1.2 一致性不变量

1. 资金表行一旦写入，金额列永不 UPDATE（只 UPDATE 状态与时间轴）；余额/冻结属**账本聚合**，用乐观锁 `version` 条件更新。
2. `tx_payments.amount > 0`、`tx_refunds.amount > 0`、余额/结算非负 —— CHECK 已全库落地（P0）。
3. Σ 明细 = 结算单：`SUM(mch_settlement_details.settlement_amount) = mch_merchant_settlement_logs.settlement_amount`（同周期）。
4. `available_balance + freeze_balance` 变化量必须由对应流水（支付/结算/提现）解释；余额表禁止“凭空”加减。

## 2. 冲正模型（不删行）

- 支付错账：以 `tx_refunds`（success）原路冲正；不入负数支付。
- 结算错账：新结算单/`status` 2-已冲减（`mch_settlement_details.status`）+ 负向明细或作废单，禁止 DELETE。
- 提现拒绝：`mch_merchant_withdrawals.status=3`（拒绝），解冻余额，禁止删申请单。

## 3. 复核 SQL（日跑/对账前跑）

- `p0_reconcile_audit.sql`（订单—支付—退款金额一致性，P0 交付，已随 P1 去掉资金表软删过滤）。
- `p1_funds_append_only_audit.sql`：确认 6 张资金表无 `deleted_at` 列、无指向资金表的删行存储过程引用。
- `p1_settlement_audit.sql`（MySQL/PG）：校验结算明细与结算单聚合一致、佣金率取值合法（0–1000）。

## 4. 双库差异

- 幂等键/渠道号唯一约束双库均有（P0 复核过）。
- PG 侧 `tx_payments/refunds` 状态为 ENUM 强约束；MySQL 为 varchar + 状态机契约（见 P0 状态机契约文档）。
- 余额乐观锁 `version` 双库均为 bigint。
