# P0 金额字段审计清单（Money Field Ledger）

> 依据 `SCHEMA_ROADMAP.md` §2 事项②“金额字段全面审计”交付。
> 基线：`sql/*.sql`（MySQL）与 `pgsql/*.sql`（PostgreSQL）双库同检。
> 审计日期：2026-09-03。审计口径：金额一律 `BIGINT` 分、`NOT NULL`、非负约束；允许负数的会计冲正须单独说明。

---

## 0. 审计结论（Summary）

- 全库货币型金额列 **统一为 `bigint` 分存储**，无 `DECIMAL`/`FLOAT` 金额残留（评分、重量、体积等非金额度量不受此规则约束）。
- 本清单覆盖 **28 个金额列 / 13 张表**（PG 侧尚未镜像 `tx_order_daily_stats`，见 §4 末尾说明）。
- 2026-10-04 增量：订单分表新增 `tx_order_daily_stats`（`gmv` / `paid_amount` / `refund_amount` 三列），**建表即带 CHECK**，故 25→28 列、12→13 表。
- 修复动作：给 **MySQL 侧缺约束的 25 列** 与 **PG 侧对应列**补上了非负/正数 `CHECK`（详见 §4 修复记录）。
- 明确例外（非金额或允许负数，已单独说明）：见 §5。

## 2. 金额语义核对（跨表口径）

- 订单：`pay_amount = total_amount - discount_amount + shipping_fee`（父/子单同口径；运费计入实付）。
- 订单项：`subtotal = price × quantity`；`Σtx_order_items.subtotal` 应等于所属子单 `total_amount`（`chk_item_price`/`chk_subtotal` 约束+日对账复核，见对账脚本）。
- 支付：`tx_payments.amount` 等于其订单当时应支付额；同一 `order_id` 允许存在多笔支付（组合支付场景在 Backlog，当前单笔为主）。
- 退款：`tx_refunds.amount ≤ 对应支付 amount − 已退成功金额`；`tx_order_items.refund_amount ≤ subtotal`；售后单 `tx_after_sales.amount` 与对应退款单一致。
- 结算：`settlement_amount = order_amount − commission_amount − refund_amount`（`mch_settlement_details`）。

> 上述口径的落地校验 SQL 见 `sql/audit/p0_reconcile_audit.sql`（MySQL）与 `pgsql/audit/p0_reconcile_audit.sql`（PG）。

## 3. 审计发现（修复前）

1. **MySQL 金额列约束不完整**：约 25 个金额列仅有 `NOT NULL` 无 `CHECK`，与“金额一律非负”约定不符（订单折扣/运费、SKU 价格、余额、提现、结算类全部缺失）。PG 镜像同缺。
2. **PG DOMAIN 定义但未使用**：`pgsql/01_domains.sql` 定义了 `money_amount` / `positive_money`，但表列均未引用，实际无约束生效（本次以显式 CHECK 对齐，域类型留作可选）。
3. **`usr_levels.discount_rate`** 默认值已修复为 1000（历史），但缺 0–1000 边界约束，本次补上。
4. **`mch_merchants.commission_rate`** 无边界（MySQL），PG 用 `permille` 域（0–1000）；MySQL 本次补 `chk_merchant_commission_rate`。
5. **比率/倍数混用**（`usr_levels.points_multiplier` DECIMAL）：属 P2“规范收敛”，非金额，不在本清单修复。

## 5. 允许负数 / 非金额字段例外清单（会计冲正须单独说明）

| 表.字段 | 说明 | 处置 |
| --- | --- | --- |
| sp_inventory_logs.change_amount | 库存变动数量（正=入，负=出） | 非金额，允许负，不设 CHECK |
| usr_points.points | 积分变动（负=扣减） | 非货币，允许负 |
| tx_order_logs / tx_payment_logs 等 | 日志快照 | 无金额列 |
| rev_* / base_* / sys_* | 无货币金额 | — |

> 若未来引入“会计冲正流水”（负数记账），必须新建专用冲正类型表或在金额表上显式放开并说明，禁止对上述金额列直接写入负数（现有 CHECK 将拦截）。
