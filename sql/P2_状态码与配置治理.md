# 状态码与配置治理（P2）

> 依据 `SCHEMA_ROADMAP.md` §4 事项⑤“状态码与系统配置治理”交付。

## 1. 原则

- **单一事实来源**：所有状态/枚举取值及其语义以本文档（词典）+ `docs/DB_CONVENTIONS.md` 为准；
  数据库列注释（MySQL `COMMENT` / PG `COMMENT ON COLUMN`）是同步副本，禁止注释与词典矛盾。
- **阈值/开关不散落在应用常量**：金额/比率单位、折扣中性值、超时、库存上限等进入统一约定；
  应用运行时可调开关按需建 `sys_config`（见 §3），不在 DB 硬编码枚举里堆业务开关。
- **新状态值必须带注释**（lint R6 强制）+ 更新本词典 + 状态机文档（若属交易状态，见 `P0_状态机契约.md`）。

## 3. sys_config / sys_dict（按需引入，本轮不建表）

约定：当出现 **≥2 处应用硬编码同一切换/阈值**、且需线上修改时，再按如下结构引入：

```sql
-- sys_config：键值开关（+ 生效范围与变更审计）
CREATE TABLE IF NOT EXISTS sys_config (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  config_key    VARCHAR(64)  NOT NULL,
  config_value  JSON         NOT NULL,
  scope_type    VARCHAR(20)  NOT NULL DEFAULT 'global', -- global / merchant / user
  scope_id      BIGINT       NOT NULL DEFAULT 0,
  description   VARCHAR(255) NOT NULL DEFAULT '',
  version       BIGINT       NOT NULL DEFAULT 0,  -- 乐观锁
  updated_by    BIGINT       NOT NULL DEFAULT 0,
  created_at    datetime(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at    datetime(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  UNIQUE KEY uk_config_scope (config_key, scope_type, scope_id)
) ENGINE=InnoDB ... COMMENT='系统配置（P2 引入时启用）';
```

- 引入条件成立时才创建，并同步 PG 镜像；不要预建空表。
- 状态码语义本身属于词典而非 sys_config（配置管“可调值”，不管“代码取值”）。
