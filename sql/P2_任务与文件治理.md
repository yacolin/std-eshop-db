# 任务与文件治理方案（P2）

> 依据 `SCHEMA_ROADMAP.md` §4 事项⑥“任务与文件治理”交付。
> 仓库无调度器/对象存储，本文件只出**方案与表结构约定**，本轮不建表（“按需要引入”）。

---

## 1. 背景与需求

需要“可追踪、可重试”的周期/异步任务，与“可追溯文件生命周期”的对象存储元数据：

- 购物车清理（`tx_carts.expired_at`）
- 积分过期（`usr_points.expire_at`）
- 统计校准（评价统计、商家销售汇总）
- 库存盘点/告警（低于 `sp_inventories.threshold`）
- 大表归档（P1 大表生命周期）
- 物流轨迹/回调重推
- 资质与媒体 URL 的上传、替换、删除（文件生命周期）

## 2. 任务执行记录表（引入时）

```sql
CREATE TABLE sys_task_runs (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  task_name     VARCHAR(100) NOT NULL COMMENT '任务名（如 cart_cleanup / points_expire / stats_reconcile）',
  run_key       VARCHAR(64)  NOT NULL COMMENT '本次运行幂等键（如 2026-08-01-01）',
  status        TINYINT      NOT NULL DEFAULT 0 COMMENT '0-运行中 1-成功 2-失败 3-超时 4-取消',
  started_at    datetime(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  finished_at   datetime(3)  DEFAULT NULL,
  affected_rows INT          NOT NULL DEFAULT 0,
  error_msg     VARCHAR(1000) DEFAULT '' COMMENT '失败原因/堆栈摘要',
  retry_count   INT          NOT NULL DEFAULT 0,
  next_retry_at datetime(3)  DEFAULT NULL,
  created_at    datetime(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  UNIQUE KEY uk_run_key (task_name, run_key),
  KEY idx_status_started (status, started_at)
) ENGINE=InnoDB ... COMMENT='任务执行记录（P2 引入时创建）';
```

规则：
- 任务内幂等键 `run_key`（日期+序号）；重复触发不重复执行（唯一键拦截）。
- 失败可重试：`retry_count < N && next_retry_at <= now` 才允许重跑；重跑产生**新 run_key**（如追加 `-r1`）并继承上下文。
- 任务结果必须幂等落地（例如清理任务“只删 created_at < cutoff 且未过期”）。

## 3. 对象存储文件元数据（引入时）

```sql
CREATE TABLE sys_file_meta (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  file_key      VARCHAR(512) NOT NULL COMMENT '对象存储 key（含桶）',
  biz_type      VARCHAR(30)  NOT NULL COMMENT 'business_license/media/avatar/qualification...',
  biz_id        VARCHAR(64)  NOT NULL DEFAULT '' COMMENT '关联业务ID',
  checksum      VARCHAR(64)  NOT NULL DEFAULT '' COMMENT 'SHA-256',
  size_bytes    BIGINT       NOT NULL DEFAULT 0,
  content_type  VARCHAR(100) NOT NULL DEFAULT '',
  status        TINYINT      NOT NULL DEFAULT 1 COMMENT '1-生效 2-待清理 3-已删除',
  uploaded_by   BIGINT       NOT NULL DEFAULT 0,
  uploaded_at   datetime(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  last_ref_at   datetime(3)  DEFAULT NULL COMMENT '最近被引用时间',
  PRIMARY KEY (id),
  UNIQUE KEY uk_file_key (file_key),
  KEY idx_biz (biz_type, biz_id),
  KEY idx_status (status)
) ENGINE=InnoDB ... COMMENT='文件元数据（P2 引入时创建）';
```

- 所有入库 URL（资质 `mch_merchant_qualifications.file_url`、媒体 `rev_review_media.media_url`、头像等）入库时同步写一条 file_meta，保证 URL 可追溯、孤儿文件可清理。
- 删除策略：状态 1→2（标记待清理）→确认无引用后 3，再由任务物理删除。

## 4. 与既有功能衔接

- 任务清理目标表已在 P1 文档（`tx_carts.expired_at`、积分过期索引 `idx_expire_at` 等）就绪；
- 归档任务消费 `p1_log_tables_audit.sql` 输出决定阈值；
- 通知模板（`base_notification_templates`）等静态数据不建任务表。
