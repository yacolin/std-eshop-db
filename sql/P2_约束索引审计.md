# 约束与索引审计规范（P2）

> 依据 `SCHEMA_ROADMAP.md` §4 事项④“约束与索引审计”交付。

## 目的

让「新增业务键都有幂等/唯一策略、常用列表与批处理查询有复合索引、无未解释重复索引、金额/资金表规则不回潮」成为可定期复检的硬约束。

## 定期审计内容（SQL 脚本）

| 检查 | MySQL 脚本 | PG 脚本 | 通过标准 |
| --- | --- | --- | --- |
| 无 FK | `p2_constraint_index_audit.sql` §1 | 同 §1 | 0 行 |
| 同表重复索引 | §2 | §2 | 0 行 |
| 空串默认值进唯一键 | §3 | §3 | 0 行（`_uq` 生成列除外） |
| 金额列类型漂移 | §4 | §4 | 0 行 |
| 资金表 deleted_at 回潮 | §5 | §5 | 0 行 |

辅助脚本：`p0_money_audit.sql`（金额 CHECK 覆盖）、`p1_*`（库存并发 / 结算聚合 / 日志表）、
`p1_log_tables_audit.sql`（大表行龄分布，供归档阈值）。

## 人工复核项（SQL 不易表达）

1. 唯一性语义：每张核心表的“天然唯一键”（如 `(merchant_id, sku_code)`）是否都有 UNIQUE；
2. 复合索引方向：列表排序（`ORDER BY status, created_at DESC`）等是否被索引支持；
3. 索引覆盖/冗余：`INCLUDE`（PG）/ 覆盖索引（MySQL 8）是否按需添加；
4. 慢查询与索引命中：结合业务慢日志每季度复核一次。

## 责任边界

- lint（`sql_lint.py` R1–R7）管“新提交不引入”；audit SQL 管“存量库定期复检”。
- 每次 migration 合并前：lint 通过 + schema diff 人工评审；每月跑一轮本审计。

- [ ] 定期调度执行（归 P2 任务治理 / 工程环境）。
