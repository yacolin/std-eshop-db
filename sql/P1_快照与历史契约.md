# P1 快照与历史数据契约（Snapshot & History Contract）

> 依据 `SCHEMA_ROADMAP.md` §3「订单快照体系」「商品版本与历史数据」「营销规则快照」交付。
> 更新日期：2026-09-03。原则：**订单/营销快照服务交易事实，商品版本表服务审计，当前主数据只服务展示与运营**。

---

## 1. 数据边界总则

- **下单即写不可变快照**：订单详情、售后、对账只读快照列，禁止回读可能变化的 `sp_products` / `sp_skus` / 地址主数据。
- **主数据可变，快照不可变**：商品改名/改价/改图/下架、地址变更不得影响历史订单展示。
- **版本表记录审计轨迹**：`sp_product_versions` 记录每次编辑 diff，不用于交易回读。

## 2. 订单快照（下单时写入，只增不改）

### 2.1 已有快照列（双库一致，无需新增）

| 表 | 快照列 | 冻结内容 |
| --- | --- | --- |
| tx_orders | `consignee/phone/province/city/district/detail_addr/zip_code` | 收货地址 |
| tx_orders | `coupon_snapshot`(json) | 优惠券名称/面值/规则摘要 |
| tx_order_items | `product_id/sku_id/sku_code` | 商品与 SKU 标识 |
| tx_order_items | `product_name/image` | 商品名与主图 |
| tx_order_items | `sku_spec_summary`(varchar) / `sku_spec`(json) | 规格摘要 / 完整规格 |
| tx_order_items | `price/quantity/subtotal` | 成交价与数量（金额快照） |
| tx_deliveries | 收货地址快照 | 发货地址回显 |

### 2.2 写入契约（服务层强制）

下单事务内（同一事务提交）必须：
1. `tx_order_items` 写入 `sku_code`、`product_name`、`image`、`sku_spec_summary`、`sku_spec`、`price` —— 全部来自**下单瞬间**的 SKU/SPU，不得留空或延迟回填；
2. `tx_orders` 地址快照取用户地址的**当前值**；
3. 命中优惠时 `coupon_snapshot` / 营销明细（见 §3）记录**命中规则与金额**，而非只记 id；
4. 售后/详情展示一律读快照列。

### 2.3 校验口径

- `Σ(tx_order_items.subtotal)` = 子单 `total_amount`；
- `subtotal = price × quantity` 由 CHECK 保障非负，等式由服务层保证；
- 对账脚本（`p0_reconcile_audit.sql`）已覆盖订单金额链，勿在快照上做减法以外运算。

## 3. 营销规则快照（下单时记录命中事实）

### 3.1 已有承载

- `tx_orders.coupon_snapshot`：券类优惠快照。
- `mkt_promotion_usage_logs.promotion_snapshot`(json) + `discount_amount`：**每张优惠单**记录活动规则快照与优惠金额（对账与营销结算用）。

### 3.2 契约

用户优惠资产核销（`mkt_user_promotions` → used）时，同事务写 `mkt_promotion_usage_logs`：
- `promotion_id`、`user_promotion_id`、`order_id`、`discount_amount`；
- `promotion_snapshot` 至少含：`promo_name`、`promo_type`、`benefit_config`（命中档）、`rule_id`、`merchant_id`、活动 `status` 快照、叠加组（若参与）；
- 不允许事后仅靠当前 `mkt_promotions`/`mkt_promotion_rules` 解释历史优惠 —— 规则可能已改/已删。

### 3.3 幂等

- `mkt_promotion_usage_logs` 一行 = 一次核销；同一 `(user_promotion_id, order_id)` 只允许一行（服务层唯一校验；MySQL 可在 `user_promotion_id` 上加唯一索引，PG 以应用幂等 + `lock_order_id` 状态机保证，见 P0 幂等文档）。

## 4. 商品版本与历史数据

- `sp_product_versions`：`product_id + version` 唯一；`diff`(json) 记录 `before/after`；`changed_fields` 列变更清单；`operator`/`operator_id` 记录操作人。
- **服务审计用途**：每次上架/改价/改名/改库存策略成功即写一条（版本从 1 递增，保留最近 10 个版本，清理由任务治理负责——见大表生命周期文档）。
- 边界：
  - 版本表 ≠ 订单快照：订单解释一律用 `tx_order_items` 快照；
  - 版本表 ≠ 当前数据：展示与售卖读 `sp_products`/`sp_skus`；
  - `sp_product_versions` 自身不允许业务软删除（`deleted_at` 列不存在）。
