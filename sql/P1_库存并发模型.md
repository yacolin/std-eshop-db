# P1 库存并发模型（Inventory Concurrency）

> 依据 `SCHEMA_ROADMAP.md` §3「库存并发模型」交付。
> 更新日期：2026-09-03。范围：`sp_inventories`（实物库存）与促销库存 `mkt_promotion_stocks`。

---

## 0. 落地的结构修正

- **MySQL `sp_inventories` 新增 `version BIGINT NOT NULL DEFAULT 0`**（乐观锁版本号），与 PG 镜像、`mch_merchant_balances.version`、`mkt_promotion_stocks.version` 同构。
- PG `sp_inventories.version` 类型由 `int` 统一为 `bigint`（与路线图约定一致）。
- 其余数量边界 CHECK（`quantity>=0`、`reserved>=0`、`reserved<=quantity`）双库已具备。

## 1. 并发扣减/预占的原子 SQL（服务层强制）

所有库存变更必须使用**单条条件 UPDATE**，禁止「先 SELECT 后 UPDATE」（会超卖）：

```sql
-- 预占（下单）：quantity 不变，reserved +N，version +1
UPDATE sp_inventories
   SET reserved = reserved + :n, status = CASE WHEN quantity - reserved - :n <= 0 THEN 3
                                              WHEN quantity - reserved - :n < :threshold THEN 2 ELSE 1 END,
       version = version + 1, updated_at = NOW(3)
 WHERE id = :inventory_id
   AND version = :expected_version          -- 乐观锁
   AND quantity - reserved >= :n            -- 可用库存足够
   AND deleted_at IS NULL;
```

```sql
-- 扣减（支付成功）：quantity 与 reserved 同时 -N，version +1
UPDATE sp_inventories
   SET quantity = quantity - :n, reserved = reserved - :n,
       version = version + 1, updated_at = NOW(3)
 WHERE id = :inventory_id
   AND version = :expected_version
   AND quantity >= :n
   AND reserved >= :n
   AND deleted_at IS NULL;
```

PG 同构（`deleted_at` 列保留时带 `WHERE deleted_at IS NULL`；MySQL 基线亦保留软删用于盘点场景）。

**验收不变量**：
1. 影响行数 = 0 ⇒ 并发冲突/库存不足 ⇒ 事务回滚，返回「库存不足或已变更」，调用方重读重试或失败。
2. 库存不可为负（数量边界 + UPDATE 条件双重保证）。
3. `reserved <= quantity` 恒成立。
4. **同一单据只产生一笔同类流水**：流水插入以 `sp_inventory_logs.reference_id_uq + change_type` 幂等（MySQL 唯一键；PG 分区表由服务层按业务号幂等，见对账文档 §6）。

## 2. 流水（sp_inventory_logs）写入约定

- 每次成功 UPDATE 后**同一事务**插入一行流水：`change_type` ∈ order_lock / order_unlock / order_deduct / inbound / outbound / return / adjust；`before_*` / `after_*` 取变更前后值，`change_amount` 带符号。
- 回滚/失败不允许写流水；允许补偿场景写 `adjust` 或 `order_unlock`，并在 `note` 注明原单据。

## 3. 促销库存（mkt_promotion_stocks）

- 已有 `version`、`chk_stock_positive`、`uk_promotion_sku(promotion_id, sku_id_uq)`；核销/锁量同样走「条件 UPDATE + version」单条 SQL，再写 `mkt_promotion_usage_logs`。

## 4. 回归用例（并发语义无法在 DB-only 仓库跑压测）

- DDL 断言：双库 `sp_inventories` 均含 `version`（tests）。
- SQL 复核：`sql/audit/p1_inventory_concurrency_audit.sql`（MySQL）/ `pgsql/audit/p1_inventory_concurrency_audit.sql`（PG）——校验表存在乐观锁列、数量边界 CHECK、库存流水幂等键存在。

## 5. 双库差异说明

| 项 | MySQL | PG |
| --- | --- | --- |
| 乐观锁列 | 本次新增 `version bigint` | 已有（类型对齐 bigint） |
| 库存流水幂等 | `reference_id_uq` 生成列 + 唯一键 | 分区表无法跨分区唯一键，服务层幂等 |
| `available` 生成列 | 无（查询时 `quantity - reserved`） | 有（STORED 生成列 + 索引） |

> `available` 生成列是 PG 独有优化，不作为一致性来源；一致性一律以原子 UPDATE 为准。
